# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

**ToDoList-AI-SDLC** is a to-do web app with a vanilla JS frontend and a Node.js/Express REST API backed by SQLite.
It is the playground for an **agentic SDLC** capstone: features are delivered end to end by the Claude Code subagents,
commands, skills and hooks in `.claude/`.

| Area | Location | Notes |
|------|----------|-------|
| Frontend | `index.html`, `JS/api.js` (fetch client), `JS/main.js` (UI, IIFE), `JS/time.js`, `CSS/` | No build step. Scripts are loaded in order by `index.html` and share globals (`TodoApi`, …). |
| REST API | `backend/server.js` → `src/app.js` → `routes/` → `services/` → `repositories/` | Express 5. Validation lives in `src/validation.js`, errors in `src/errors.js` (`ValidationError` 400, `NotFoundError` 404). |
| Database | `db/schema.sql`, `db/seed.sql`, `db/init.js`, `backend/src/db.js` | better-sqlite3. The schema is applied on every open (`CREATE … IF NOT EXISTS`). |
| Tests | `tests/unit/*.test.js`, `tests/api/*.test.js` | Jest 30. The frontend tests use jsdom and a fetch mock. The API tests use supertest with an in-memory DB. |
| SDLC artifacts | `docs/sdlc/<JIRA-KEY>/` | One folder per ticket |

## Commands

```bash
npm install
npm test                      # all Jest suites
npm run test:unit             # tests/unit only
npm run test:api              # tests/api only
npx jest --coverage           # coverage report
npx jest tests/unit/frontend.test.js -t "AC-1"   # a single test by name
npm run db:init               # create and seed data/todos.db
npm start                     # http://localhost:3000
npm audit
```

## Conventions

- **Layering:** routes stay thin, services hold the rules, repositories hold the SQL (prepared statements only), and validation is pure.
- **API errors** have the shape `{ error: { message, details? } }`. Throw `ValidationError`, `NotFoundError` or a new `AppError` subclass. Never send raw errors.
- **Frontend:** build DOM with `create()` and `textContent`. Never use `innerHTML` with user data. Every API call goes through `TodoApi`.
  New browser modules are plain scripts that expose one global and are added to `index.html` *before* `main.js`, and also to the `scripts` map in `tests/unit/frontend.test.js`.
- **Ids** (EPMCDMETST-68130) are lowercase v4 UUID strings, generated by the client (`TodoModel.newId()`) and validated by the server. Never coerce ids with `Number()`.
- **Tests:** name new tests after requirement IDs (`AC-3: …`). Keep the jsdom fetch mock in `frontend.test.js` behaving like the real API.
- **No new dependencies** without an explicit architecture decision.
- On Windows, git uses `core.autocrlf=true`, so do not assert on raw line endings of checked-out files.

## Agentic SDLC

Run `/sdlc <JIRA-KEY>` for the full 8-step flow, or run the steps one by one:

| Step | Command | Agent(s) / skill | Artifact (`docs/sdlc/<KEY>/`) |
|------|---------|------------------|--------------------------------|
| 1 Requirements | `/requirements <KEY>` | requirements-gathering | `user-story.md`, `requirements.md` (committed) |
| 2–3 Architecture + design review | `/design <KEY>` | architecture-designer ⇄ design-reviewer | `architecture.md`, `design-review.md` |
| 4 Implementation planning | `/plan <KEY>` | implementation-planner | `impl-plan.md` |
| 5 Implementation | `/implement <KEY> [T1-T4]` | feature-implementer + `dto-generator` | source + tests |
| 6 Review | `/review <KEY>` | code-reviewer ⇄ feature-implementer | `code-review.md` |
| 7 Verify | `/verify <KEY>` | test-suite-generator + `doc-quality-check` | `verification-report.md` |
| 8 PR | `/create-pr <KEY>` | pr-creator | `CHANGELOG.md`, `pr-description.md`, PR |

Rules for every agent:
- Each step reads the previous step's artifacts. Do not skip steps or human-in-the-loop gates.
- Branches are `feature/<KEY>-<slug>`. Commits are `<KEY>: <imperative summary>`. Never commit or push to `master`.
- Hooks: `guard-git.mjs` blocks force pushes, pushes to master/main, and commits containing secrets or `node_modules/`.
  `test-on-edit.mjs` runs the related Jest tests after every edit under `JS/`, `backend/`, `db/`, `tests/` or to `index.html`.
- Jira access goes through the `jira` MCP server (`.mcp.json`). Never paste tokens into files or prompts.
- Stage files explicitly. Local folders such as `.idea/`, `reports/` and `docs/codemie/` must not be committed.
